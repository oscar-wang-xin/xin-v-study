# 视频转摘要 — 详细工作流

本文件是 `xin-v-study` 的执行细则。SKILL.md 负责调度, 本文件负责"每一步到底怎么做才算到位"。

---

## 前置: 帮助模式与输出目录确认

**帮助模式**: 用户没给视频、或在问用法/能力/帮助时, 读 `references/help.md` 讲清输入形式、保存位置、产出、边界, 然后停下等用户给视频。此时不做转录、不生成任何文件。

**输出目录确认** (给用户视频但没说存哪时必做): 用宿主提供的提问/交互能力提示三选一 (没有专门提问工具就在对话里直接问)——

1. 配置默认目录: 读 `config.json` 的 `default_output_dir`, 在选项描述里写出实际路径, 标为推荐。
2. 当前工作目录。
3. 其他路径: 用户自由输入完整路径。

拿到选择才继续。**不能因为配了默认目录就跳过询问**; 默认目录只是推荐选项。用户明确指定了目录则直接用, 不询问。目录一旦确定, 后面所有步骤 (包括步骤 5 的导航页更新) 都用这一个目录。

**宿主转录能力检测** (前置做, 决定步骤 0 和步骤 2 的走法): 检查当前可用工具里有没有"音视频转文字"的能力。有 → 记下"路径 A" (宿主原生转录, 效率更高), 步骤 0 可跳过本地引擎安装; 没有 → 记下"路径 B" (本地脚本兜底), 步骤 0 保持全装。检测结论全程沿用, 不要到步骤 2 再反复横跳。

---

## 步骤 0: 依赖准备

运行 `<skill_dir>/scripts/bootstrap.py`, 确认 `imageio-ffmpeg`、`yt-dlp`、`faster-whisper` 可用。
首次运行会联网安装, 后续幂等跳过。若前置检测为路径 A (宿主原生转录), 用 `python bootstrap.py --no-asr` 跳过本地转录引擎, 省时省空间; 路径 B 保持全装。

抽帧和抽音频只依赖 `imageio-ffmpeg` 自带的 ffmpeg 二进制, **不要求系统全局安装 ffmpeg**。
转录引擎 `faster-whisper` 是纯本地库, 模型在首次转录时才下载并缓存, 之后离线可用。
整个流程全部是普通 Python 命令行, **不依赖任何宿主专有工具**, 任何能执行命令的 Agent 都能跑通。

---

## 步骤 1: 把来源变成一张本地视频

运行 `download_video.py <source> <work_dir>`。

- `source` 是本地已存在的路径 → 原样返回绝对路径, 不复制、不改动原文件。
- `source` 是 `.mp4/.m4a/...` 媒体直链 → 直接下载。
- `source` 是网页地址 (B站/YouTube 等) → 调用 yt-dlp 取最优 mp4, 不下载播放列表。

`<work_dir>` 是中间产物目录, 建议用系统临时目录 (如 `tempfile.mkdtemp()`)。
**最终 HTML 不放在 work_dir**, 按步骤 5 的输出规则决定位置。

### 平台登录态

B站的会员清晰度、年龄段内容, YouTube 的部分视频需要 cookies。
遇到 yt-dlp 报 403 / "sign in to confirm" 时, 不要硬编凭据, 按下面顺序处理:

1. 让用户提供 cookies 文件, 或
2. 让 yt-dlp 从浏览器读取 (`--cookies-from-browser chrome/edge/firefox`), 或
3. 退而取最低可用清晰度 (在脚本的 `-f` 参数中调整 format 选择)。

仍失败就如实告知用户, 不要用别的内容顶替。

## 步骤 2: 提取讲解内容 (转录)

**这是内容的主要来源。** 讲解类视频的信息在语音里, 文字稿优先于画面。

**按前置环节已记录的检测结论, 二选一, 只走一条:**

1. 路径 A: 宿主自带"音视频转文字"能力 → 用原生转录 (效率更高)。
2. 路径 B: 宿主没有该能力, 或路径 A 失败 → 用本地脚本 (任何 Agent 通用)。

两条路径产出同一份文字稿, 后续步骤完全一样。

### 路径 A: 宿主原生转录 (优先)

检查当前可用工具里有没有音频/视频转录能力。不同宿主形态不同: 例如 WorkBuddy 里搜索并加载 `AudioTranscribe`, 传 `{"filePath": "<本地视频绝对路径>"}`, 直接吃 mp4、无需先抽音频; 其他宿主若有同类工具同样适用。
命中就用, 省去模型下载和本地推理。若工具报错、要登录态或超上限, 立即回退路径 B, 不要卡住。
文字稿同样只作分析素材, 不写进 HTML。

### 路径 B: 本地转录脚本 (兜底)

运行随 skill 分发的 `scripts/transcribe.py`:

```bash
python <skill_dir>/scripts/transcribe.py "<本地视频绝对路径>" --language zh --out <work_dir>/transcript.txt
```

- 默认语言自动检测, 输出纯文字稿; 中文视频加 `--language zh` 更准。
- 默认模型 `small` (中文可用); 准确率不够用 `--model medium` 或 `large-v3`; 有 NVIDIA 显卡加 `--device cuda --compute-type float16` 提速。
- 需要时间戳用 `--timestamps` (每行带 `[起-止]`) 或 `--srt` (标准字幕)。
- 脚本自动用 `imageio-ffmpeg` 抽 16 kHz 单声道音频再识别, 找不到 ffmpeg 时回退到直接解码原文件。
- 首次运行缺引擎/模型时, stderr 会给出 `pip install faster-whisper` 和国内镜像 (`HF_ENDPOINT`) 的设置方法; Step 0 已提前装好引擎, 正常情况下这里只等模型首次下载。
- stdout 只输出文字稿, 诊断走 stderr; 也可用 `--out` 落盘, 两种方式取其一即可。

得到的是带口语痕迹的原始文字稿。它只进了你的分析上下文, **不要原样塞进 HTML**。

### 超长视频 (内存吃紧时)

本地脚本内部按 VAD 自动分段, 没有 1 GB / 5 小时的硬上限, 绝大多数视频直接整段转录即可。
极长音频若内存吃紧, 用 `imageio-ffmpeg` 的 ffmpeg 二进制按时间切片, 逐段转录后按时间顺序拼接。
切片用 `-ss <起点> -t <时长> -c copy` 避免重编码, 保证内容不失真。

### 无声 / 纯画面视频

转录结果为空时, 退化为"关键帧视觉理解": 逐帧读取画面中的文字与场景 (用当前宿主的多模态看图能力),
据此归纳。**此时必须在摘要中说明"视频无讲解语音, 摘要基于画面内容"**, 不能伪装成语音转录。

## 步骤 3: 抽取配图

运行 `extract_frames.py <video> <work_dir>/frames --count 8`, 得到:

- `frame_001.jpg` ... : 视频真实画面, 均匀覆盖全片
- `manifest.json`    : 每张图对应的时间点 (秒)

抽帧是等比缩放的真实截图, 不做生成或篡改。帧数默认 8, 视频越长可加到 10-12, 但不要堆图。

用当前宿主的多模态看图能力读取抽出的帧, 理解每张画面讲的是什么, 与文字稿对应起来。
**选图纪律**:

- 只选和摘要段落内容真正对得上的帧, 对不上的宁可不用。
- 一图配一段, 不要一段塞多图, 也不要图文各说各的。
- 封面/片头/片尾的 logo 帧、黑屏、纯字幕过渡帧一律丢弃。
- 图注写清楚"视频 XX:XX 处画面", 让图有出处, 不是装饰。

---

## 步骤 4: 归纳摘要 (核心纪律)

这一步决定成品质量, 严格遵守以下六条:

1. **只保留视频真讲了的东西。** 不补充背景知识, 不联想, 不替作者圆场。视频没说的, 一个字都不写。
2. **去口语噪声。** 删掉"嗯/啊/呃/那个/就是说/然后呢/对吧/是吧/这个这个/怎么说呢"以及重复代码、口头禅、和主题无关的闲聊。删完读起来要像人写的书面语, 但仍是**视频的原意**。
3. **不失真。** 不改变结论、不夸大、不弱化。数字、专有名词、人名、产品名逐字核对转录稿。
   拿不准的表述用保守说法, 不要替作者下判断。
4. **不扩展。** 摘要篇幅控制在原文字稿的 20%-35%。这是摘要, 不是读后感, 也不是二次创作。
5. **重点突出。** 先给一句"核心结论", 再给 3-6 个要点, 每个要点用一句话说清。
   宁可少而准, 不要多而散。
6. **保留结构信号。** 视频里明确的"第一/第二/最后""分三点讲"这类顺序, 原样保留, 不要打乱作者的表达结构。

### 标题提取

从转录稿里提炼标题, 不是简单截第一句。要求:

- 准确概括视频主题, 让人一眼知道讲的什么。
- 短, 一般 8-24 个汉字, 不用"详解/教程/分享"这类空词凑数。
- 如果视频开头作者自报了标题, 优先采用原标题。
- 标题同时用作 HTML 的 `<title>` 和文件名。

## 步骤 5: 生成单页 HTML

读取 `references/design_guide.md` 和 `assets/report_template.html`, 按其中的规范生成。
模板已内置 8 套配色切换、大纲导航、回到顶部与滚动进度; 生成时只填内容占位符,
不要重写这些交互逻辑, 也不要手改模板里的配色变量。大纲条目由脚本在浏览器里从章节标题自动生成。

### 输出位置

沿用本文件开头"前置"里已经确认的目录, 一次确认全程使用:

- 用户在本次请求里指定了目录 → 存到那个目录 (目录不存在就创建)。
- 没指定 → 此时应已在前置环节用提问/交互能力问过并拿到选择; 按用户选的存。若因故还没问, **先问再写**, 不要静默用默认目录。
- `config.json` 的 `default_output_dir` 只是询问时的推荐项, 不是自动答案; 未配置则读 `config.example.json`, 再退化为项目根目录的 `output/`。
- **不要**自作主张存到 skill 安装目录或临时目录。

### 文件名

用 `sanitize.py "<标题>"` 清洗后加 `.html` 后缀。保证在 Windows / macOS / Linux 都合法。

### 自包含

HTML 必须是**单个文件**:

- CSS、必要的少量 JS 全部内嵌。
- 关键帧图片用 base64 data URI 内嵌 (`data:image/jpeg;base64,...`), 不引用外部图片文件。
- 知识脑图由模板脚本从章节标题自动生成, 无需手写 SVG 或填占位符; 章节标题超长截断失真时才加 `data-mind` 短标签, 规则见 `references/mindmap_guide.md`。无章节时整块自动移除。
- 不引用任何外部 CDN / 字体 / 脚本。断网也能完整打开。

### 信息图 (可选)

视频有清晰的流程、并列要点、对比或时间线时, 按 `references/infographic_guide.md` 用内联 SVG 画一张"一图看懂":

- 图上每个字都来自转录稿, 主标题一句 + 3-5 个信息块, 每块标题≤10字、说明≤18字。
- 版式按内容结构选 (流程 / 编号卡片 / 对比 / 时间线), 一页只放一张图。
- 不要交给生图工具猜中文, 会出错字; 内联 SVG 文字可控、不失真、无外部依赖。
- 内容没有清晰结构、要点不足 3 个、或超过 6 个砍不下来 → **整段删掉** `<section class="infographic-block">`, 不留空壳。

### 收尾

生成后用当前宿主的预览能力打开成品, 让用户直接看到结果。正文末尾保留一句客观说明:
"本摘要基于视频讲解内容整理, 未做外延扩展。" 不要加任何署名或落款。

### 更新导航页

运行 `scripts/update_index.py <输出目录>` (省略参数时用默认目录)。脚本扫描该目录顶层的全部
HTML 摘要 (自动排除 `_list.html`), 重建卡片导航页。

提取元数据时优先读摘要 head 里的结构化 meta:

| meta name | 用途 |
|---|---|
| `video-title` | 卡片标题 |
| `summary-desc` | 卡片简介 (填核心结论) |
| `video-source` | 卡片来源 |
| `summary-date` | 卡片创建日期, 也是默认排序依据 |
| `video-duration` | 卡片时长 |

meta 缺失时脚本会从页面正文降级提取, 但可靠性较差, 所以生成摘要时必须把 meta 写实。
`content` 属性里若含引号, 写成 `&quot;`, 避免破坏标签。

导航页默认按创建时间倒序 (最新在前), 支持切换为名称排序、升降序、关键词实时搜索,
点击卡片在新窗口打开对应摘要。每次新增摘要后都要重新运行脚本, 导航页不会自动感知文件变化。

## 失败处理

| 情况 | 处理 |
|---|---|
| 来源打不开 / 下载失败 | 如实报错, 说明具体原因, 不生成摘要 |
| 转录为空但画面有内容 | 走视觉退化路径, 并在摘要中注明来源为画面 |
| 转录质量差 (大量乱码/听不清) | 在摘要开头提示"转录质量有限, 以下内容仅供参考", 不臆测补全 |
| 抽帧失败 | 摘要照常产出, 改为纯文字版式, 不编造配图 |
| 视频内容超出理解范围 | 保守归纳能确定的部分, 明确标注哪里不确定 |
